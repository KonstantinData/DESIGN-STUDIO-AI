# API contract

Same-origin JSON API under `/api`, cookie authorization. The tenant is derived exclusively from the configured Host. No client tenant selector. All POST/DELETE requests require exact `Origin: https://<host>` and `X-CSRF-Token` from GET session. No bearer tokens or private media in URLs.

- `GET /api/config` → `{brand,expert_name,turnstile_site_key,generation_ready,blocked_reason}`.
- `GET /api/session` → `{id,csrf_token,changes_remaining,studios:[{id,status}]}`; creates HttpOnly Secure SameSite=Strict `__Host-studio` cookie. 30 days fixed lifetime.
- `POST /api/studios` multipart: `prompt`, `source_kind` (`text|photo|floorplan`), optional `file` PNG/JPEG/WebP ≤12MB, `challenge_token`; `Idempotency-Key` header required. Returns studio with 202. Exactly one start per session; three parallel durable image jobs after master briefing, individual results visible through polling.
- `GET /api/studios/{id}` → studio shape below.
- `POST /api/studios/{id}/revisions` JSON `{concept:"A"|"B"|"C",kind:"material"|"layout",instruction,base_revision_id,challenge_token}` + Idempotency-Key → `{job_id}` 202. Up to five successful changes; failure returns credit.
- `POST /api/studios/{id}/select` `{revision_id}` → studio. Selection and rollback never call a provider.
- `GET /api/media/{id}` or `?download=1`: private authenticated image, no public static route.
- `POST /api/session/resume-token` → `{token}`. This secret must be copied securely; current token is replaced. No token in URL.
- `POST /api/session/resume` `{token}`: rotates session authentication, consumes resume token. GET session first to receive CSRF protection, then GET session again after resume.
- `DELETE /api/session`: 204, deletes relational session data and local media; outstanding provider outcomes cannot republish a deleted session. Conservative cost audit retained without media/contact data.
- `POST /api/studios/{id}/handoff` `{revision_id,media_ids:[],name,email,message,consent:true}` transfers only selected revision, required briefing and explicitly selected images. Only configured tenant HTTPS destination; success requires explicit downstream `{accepted:true}`.
- `GET /healthz` verifies PostgreSQL connectivity.

Studio: `{id,status,error,room,assumptions,selected_revision_id,changes_remaining,concepts:[{key,title,status,error,revisions:[{id,media_id,number,kind,image_url,download_url,curation:[string,string,string],assumptions,created_at,room_version}]}]}`. Status values `queued|running|completed|partial|failed`. Room: `{version,description,features:[{name,value,provenance:"USER_GIVEN"|"DETECTED"|"ASSUMED"|"UNKNOWN"}],constraints:[]}`. Every revision stores immutable master-briefing snapshot. Errors use `{detail:string}` and honest HTTP 4xx/5xx. Poll every 1.5–3s while queued/running; errors for one initial concept do not block others.

## Explicit release blockers

This implementation has no real provider acceptance evidence, invoice-cost reconciliation, independently proven distributed per-IP bot/abuse limits, verified downstream Handoff service or backup/external-processor deletion proof. Automated image checking does not replace manual geometry acceptance. Public release remains blocked.

`POST /api/studios/{id}/room` JSON `{description,features:[{name,value,provenance:"USER_GIVEN"}],constraints:[],confirm_global:true}` explicitly increments the shared room version. No provider call; old room snapshots retained in room_history and each revision immutable briefing. Old revisions expose `previous_room_basis:true`. Subsequent chosen revisions use corrected room + selected concept origin.

Handoff requires client `Idempotency-Key` and per-tenant server secret `HANDOFF_AUTH_<SLUG_UPPER_WITH_UNDERSCORES>`; unknown downstream outcome is never automatically replayed. Destination receives authenticated bearer authorization, no redirects. Runtime emergency stop: create `DATA_DIR/STOP_GENERATION` on shared private volume. Every reservation checks this file; calls already in flight remain within their reserved ceilings. Removal never overrides the independent environment/tenant stops.

Development validation: `uv sync --frozen`; `python -m pytest -q`. PostgreSQL integration tests additionally require `TEST_DATABASE_URL` pointing to a **disposable database**, as integration fixtures drop/create their schema. No SQLite fallback. Tests inject `ControlledProvider` solely as test evidence; no production test-provider switch exists. Upgrade/downgrade initial migrations verified twice on PostgreSQL 17.

Room corrections merge by feature name (case-insensitive) and preserve unmodified provenances; only explicit user corrections receive USER_GIVEN. Constraints are additive. Each revision includes `review` metadata with automated shadow observations and requires human acceptance; critical findings consume no user change credit. No real visual/geometry acceptance is claimed.

Actual cost remains `null` until independently verified provider billing evidence is reconciled. Operator command `python -m app.reconcile RESERVATION_ID ACTUAL_CENTS /private/evidence.json` requires a matching recorded provider request ID, provider billing record ID, verifier identity and actual rounded-up USD cents; evidence SHA-256 is retained, no secret data copied. Only then may conservative ceiling exposure be released. Any actual amount above its ceiling disables that tenant and exhausts the global remaining cap. Unknown/failed outcomes lacking provider request evidence never receive an assumed refund. Default $1-image ceilings make 15-image execution inside a $5 cap infeasible without verified reconciliation or independently verified safer ceilings; this is a live-run gate, not authorization to exceed the cap.

## Request and abuse boundaries

API mutation bodies are limited **before multipart/JSON parsing**, including chunked transfers: upload requests 13 MiB; other mutations 32 KiB; overall body receive deadline 20s. Images themselves must be JPEG/PNG/WebP, 256–4096 px each side and ≤12 MiB, with EXIF orientation normalized and metadata removed. Provider calls have independent overall deadlines (text90s, image240s, curation90s), not merely per-socket read timeouts. Timeouts/cancellations retain full conservative exposure. Proven local `ProviderPreflightError` records `released_no_call` and actual zero without making any transport request; provider/transport/response failures never receive this release.

PostgreSQL upsert counters enforce anonymous session admission per source (default10/hour) and mutation limits (30/minute), independent of cookie rotation and across API replicas. Counter IDs contain only HMAC-pseudonymized IP/tenant/window data, daily-rotated; no raw IP/fingerprint is persisted. Counters expire automatically. Only an immediate peer in `TRUSTED_PROXY_CIDRS` may supply X-Forwarded-For; unknown peers cannot spoof their source. Ports/casing do not split the tenant's counter. `RATE_LIMIT_SECRET` may supply a private≥32character HMAC key, otherwise an atomically generated mode0600 shared-volume key is used. Global session admission and provider budgets remain independent defenses. These are implemented controls, not a substitute for real production abuse/load validation.

Critical shadow observations now produce `review_required` job/concept/studio status, with images/reports retained for honest human review and no successful-change credit. They never constitute accepted geometry. The latest concept job error replaces stale historical error messages; each revision's assumptions derive from its immutable briefing snapshot.

`DELETE /api/session/resume-token` explicitly revokes the current continuation token without deleting the session. All standard Origin/CSRF protections apply.

## Backup-safe deletion

`DELETION_LEDGER_DIR` must be a separately retained private volume, independent of DB/media backup restore. Session deletion and 30-day expiry fsync a minimal tenant/session UUID tombstone before removing relational/media data. `python -m app.privacy replay` replays the latest ledger **and removes expired sessions**, reporting aggregate counts only. API and worker startup replay before serving/working. Restore must supply the latest independently retained ledger; restoring an old snapshot must never replace it with an old ledger. `python -m app.privacy status` reports count without identifiers. Local media GC only touches canonical UUID media filenames, preserving keys, tombstones and operator configuration. External provider/backup retention still requires operator-proven policy and restore evidence.

## Privileged private provider smoke

`python -m app.smoke --host TENANT --state /private/smoke-state.json --report /private/smoke-audit.json` is read-only inspection. Adding `--execute --prompt-file /private/impulse.txt --gate-file /private/verified-gate.json` submits exactly one real text workflow to the normal durable worker, only after attested project/hard-limit/pricing/kill-switch gates and persisted tenant/global caps≤500c. This is privileged local operator access; there is no public endpoint, bot-disable switch or runtime fake provider. It is explicitly **not public Bot E2E acceptance**. Private state stores a genuine session cookie mode0600 so authorized media can later be inspected through ordinary APIs. No real smoke was executed during implementation.

## Verified price-based exposure accounting

Default behavior remains full conservative ceiling charging. To enable conservative usage-based **upper-bound accounting**, an operator may configure `VERIFIED_PRICING_FILE` outside the checkout and independently pin its exact bytes using `VERIFIED_PRICING_SHA256`. The regular file must be private (no group/other permissions), owned by the service/root, ≤64KiB, and carry a dated identifiable verification plus an unexpired authoritative HTTPS OpenAI pricing source. No live rates ship in this repository.

Contract fields: `version:1`, `currency:"USD"`, `verified_by`, timezone-aware `verified_at`/`expires_at`, `source`, and `models` keyed by **exact verified model identity**. Responses entries require `kind:"responses"`, `input_usd_per_million`, `output_usd_per_million`. Image entries require `kind:"image"` plus `text_input_usd_per_million`, `image_input_usd_per_million`, `text_output_usd_per_million`, `image_output_usd_per_million`. Rates must be explicit nonnegative decimal strings verified by the operator; no example price values imply a current tariff.

Successful calls may settle to `priced_upper_bound`: raw measured usage, exact model identity/basis, immutable contract hash/reference/rate snapshot, rounded-up exposure cents and `accounting:"verified_price_upper_bound_not_invoice"` are retained. `actual_cost_cents` stays null until provider invoice reconciliation. Responses use returned exact model identity (an unverified snapshot/alias mapping cannot release funds); image usage uses the exact requested model because the Images response schema omits model identity. Cache discounts are ignored. Image input splits must exactly match totals; absent output splits use the more expensive verified output rate. Missing/malformed usage, unknown model, unavailable/changed/expired contract or failed call retain the full ceiling. A computed upper bound above the reserved amount disables the tenant and globally exhausts remaining headroom. Locks preserve exactly-once accounting; 64-bit monetary columns preserve large conservative exposure without integer overflow. Invoice reconciliation adjusts from the already-accounted bound, never twice from the original reservation.

The operator audit reports exposure upper bounds and actual invoices separately. This feature makes approved capped runs feasible when authoritative prices and successful complete usage justify releasing excess reservations; it does not prove those rates or authorize paid calls by itself.

A valid pinned current pricing contract covering **both configured request models** is now a mandatory pre-call gate in readiness and immediately before each paid invocation. Missing/changed/expired contracts prevent any provider transport and create no reservation/charge. The conservative full-ceiling fallback applies only to uncertain **outcomes after an already-authorized call**, including missing response usage/model identity or a contract that changes while the call is in flight. Tests install explicitly synthetic contracts in disposable QA fixtures; no production testing bypass exists.

Deployment: mount the operator-provisioned private pricing-contract volume read-only at `/etc/studio/pricing`; use `/etc/studio/pricing/verified.json`, owner service UID10001, mode0600, and pin the exact SHA-256 in the private environment. Provision atomically using a one-shot privileged container with temporary write access to that named volume; never grant the running application a writable pricing mount. Preserve archived verified contracts/sources independently for audit. No provisioned rates or verification claims are supplied by source code.

Private operator smoke continuation now supports `--action material` or `--action layout` with `--execute --instruction-file /private/instruction.txt --gate-file /private/verified-gate.json`, using the same `--host`, `--state` and `--report`. Both changes independently reference the durable **original initial A**. The CLI checks the saved session cookie/hash, tenant ownership, expiry/revocation, all three noncritical initial concepts on one room version, terminal previous jobs, successful-change quota and unchanged ≤500c caps. Each action has a deterministic once-only durable job key; uncertainty is investigated through audit rather than a second paid submission. Private inspection remains read-only; expected images advance from three to four/five. The production HTTP API still requires genuine Turnstile for every generation. This trusted local procedure exercises provider/worker functionality, never public Bot E2E or human visual acceptance.

For an authoritatively documented image model that cannot produce text output, its operator-verified pricing entry may explicitly set `text_output_supported:false`; `text_output_usd_per_million` must then be absent or null. No zero text-output tariff is invented. Image-only output is bounded at the verified image-output rate; any reported nonzero text-output tokens contradict that capability and retain the full reservation. Malformed flags or contradictory numeric text-output tariffs invalidate the contract. Entries omitting this flag preserve the existing supported-text-output behavior. This schema support changes no public default model and does not authorize a model switch or paid call.

A paid invocation now first checks the anonymous fixed HTTPS `/v1/models` route with normal TLS verification and no API Authorization header. Only upstream HTTP200/401/405 establish reachability; redirects, proxy/connect/timeouts and other responses fail closed. The total probe deadline is5s (connect2s), with a process/event-loop success cache20s and failure cache2s. The probe occurs after readiness/pricing gates and before any reservation/model call: proven route failure books no model charge. This is availability evidence only; a later paid transport can still fail and must retain its full conservative reservation. No key values, proxy details or raw errors are recorded. This source change was prepared after a real stale-proxy failure; existing unknown earlier costs remain unchanged.

Read-only model-list success is **network/read-route evidence only**: HTTP200 on `GET /v1/models` does not establish write authentication for Responses or Images and may be served without valid write credentials. The actual protected provider request remains authoritative for its own authentication outcome. Availability probes never authorize a paid retry, repair credentials or release unknown earlier costs; those require separate operator diagnosis and the normal explicit spending gates.

## Observed credential-routing blocker

After two bounded private text attempts, no image was produced. The first attempt lost its proxy connection before receiving an HTTP response; the second reached Responses and returned HTTP401 with sanitized `invalid_api_key`. Read-only diagnosis then established that `GET /v1/models` returns HTTP200 even without Authorization or with a deliberately invalid bearer, so that endpoint cannot validate this environment's write credential. One explicitly authorized invalid empty-JSON `POST /v1/responses` (no model/input and no generation) returned HTTP401 `invalid_api_key` both on the host and inside the worker; in-process comparison confirmed the injected binding was identical. Provider code uses the expected fixed HTTPS origin, Bearer header and proxy configuration consistently.

The concrete blocker is an injected credential binding currently unusable for Responses writes. Available evidence cannot distinguish an incorrect underlying stored value from a platform POST credential-forwarding defect; it does **not** establish that the user's project key is wrong. Resolve the platform's stored binding/POST substitution with the existing binding before requesting duplicate keys. Generation remains closed. The two uncertain attempts retain a combined conservative20c exposure, reserved0; these are not proven invoice costs. Further paid retries are not authorized by a successful model-list response.

Optional `OPENAI_REFERENCE_IMAGE_MODEL` selects a separately verified image model whenever a reference image is present (photo/floorplan initial concepts and all revisions). Empty/unset preserves the existing generation-model behavior. Text-only initial images continue to use `OPENAI_IMAGE_MODEL`. The actual request payload and recorded model identity use the selected model; readiness additionally requires its explicit pricing entry when configured, and the per-call pricing gate verifies that selected request identity. Reference inputs are checked before transport for maximum4096px and aspect ratio≤16:1 so the documented conservative reference-token bound cannot silently be exceeded by malformed upstream image dimensions. This source support does not change any deployed model, enable generation, authorize spending or establish human image quality.
